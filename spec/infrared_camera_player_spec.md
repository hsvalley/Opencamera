# 红外摄像头播放软件规格书

## Summary
- 目标技术栈：`Python + PySide6/Qt + OpenCV`
- 采集方式：普通 UVC 视频流统一通过 `cv2.VideoCapture` 获取
- 支持两类摄像头模式：
  - 普通摄像头：直接显示原始视频
  - 红外摄像头：对原始 UVC 帧执行温度重建、裁剪线性拉伸、中值滤波、伪彩映射后显示
- 首版面向单机桌面播放器，不包含录像、截图、参数持久化、温度测量标注

## UI 与交互
- 主窗口包含三个核心控件：
  - 摄像头类型下拉框：`普通摄像头` / `红外摄像头`
  - 摄像头设备下拉框：列出系统摄像头真实名称
  - 显示开关区：
    - 普通摄像头模式：1 个开关，控制原始画面显示开/关
    - 红外摄像头模式：2 个开关，分别控制灰度图显示开/关、伪彩图显示开/关
- 画面区行为：
  - 普通摄像头模式：单画面显示原始视频
  - 红外摄像头模式：最多双画面并排显示灰度图与伪彩图
- 切换摄像头类型或设备时，先释放当前 `VideoCapture`，再打开新设备
- 打开设备失败、读取帧失败、帧尺寸异常时，界面给出错误状态，不保留旧画面误导用户

## 采集与设备枚举
- 视频采集统一使用 `cv2.VideoCapture`
- 设备枚举允许通过 Windows 只读查询拿到真实设备名称，再和可打开的 OpenCV 索引做顺序配对
- 设备项内部数据结构固定包含：
  - `display_name`
  - `camera_index`
  - `backend_hint`
- 首版默认按当前红外设备规格处理：
  - 实际红外图尺寸固定为 `260 x 202`
  - UVC 逻辑宽度为 `520`
  - 红外模式采集时尝试设置 `CAP_PROP_CONVERT_RGB=0` 和 `YUY2`

## 红外处理流水线
- 输入帧按 UVC `YUV422` 接收，但业务上视为“每个红外像素占 4 个字节的原始承载流”
- 红外温度重建规则：
  - 每个实际像素对应 4 字节：`b0 b1 b2 b3`
  - 取每个字节高 4 位，按接收顺序高到低拼成 16 位值：
    - `value16 = (b0_hi << 12) | (b1_hi << 8) | (b2_hi << 4) | b3_hi`
  - 实际有效值取低 14 位：
    - `temp14 = value16 & 0x3FFF`
- 处理步骤固定为：
  1. 从 UVC 原始帧重建 `260 x 202` 的 `temp14`
  2. 对 `temp14` 执行裁剪线性拉伸，输出 `8-bit` 灰度图
  3. 对灰度图执行二维中值滤波，默认采用 `cv2.medianBlur`
  4. 基于滤波后的灰度图执行分段线性伪彩映射，输出 RGB 图
- 首版参数固定：
  - 裁剪比例：`0.005`
  - 中值滤波核：`3`
  - 伪彩规则：沿用现有脚本的分段线性风格

## 模块与接口
- `CameraEnumerator`：枚举 Windows 摄像头名称与索引
- `CaptureController`：打开、关闭、切换 `cv2.VideoCapture`
- `FrameRouter`：根据摄像头类型选择普通路径或红外路径
- `InfraredProcessor`：完成温度重建、拉伸、滤波、伪彩
- `MainWindow`：Qt 主界面与状态同步
- 关键数据接口：
  - `CameraDevice { display_name, camera_index, backend_hint }`
  - `InfraredFrame { temp14, gray8, pseudo_rgb }`
  - `DisplayState { show_normal, show_gray, show_pseudo }`

## Test Plan
- 设备枚举：
  - 能列出系统摄像头名称并绑定索引
  - 无摄像头时下拉框为空且界面显示可理解错误
- 普通摄像头模式：
  - 选择普通摄像头后可正常打开并显示原始画面
  - 关闭显示开关后停止刷新画面区域，不产生崩溃
  - 切换设备时旧设备被释放，新设备接管
- 红外摄像头模式：
  - 对 `260 x 202` 样帧可正确重建 `temp14`
  - 字节高 4 位拼装顺序正确，不出现镜像、错位、强度异常
  - 裁剪拉伸后输出 `8-bit` 灰度图
  - 中值滤波生效且不改变输出尺寸
  - 伪彩图由灰度图稳定生成，色带符合分段线性规则
- UI 联动：
  - 红外模式下灰度图、伪彩图两个开关可独立控制显示
  - 普通模式切回红外模式时，控件区状态与画面区同步更新
  - 打开设备失败、读取帧失败、帧尺寸异常时，界面给出错误提示且程序不中断
